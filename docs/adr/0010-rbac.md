# ADR-0010: Role-based access control per workspace

- Status: Proposed
- Date: 2026-10-15
- Deciders: product owner (@amandavictoriacouto)
- Related: [MVP architecture](../architecture/mvp-architecture.md), [threat model](../security/threat-model.md)

## Context

Approvals and policy changes must be restricted by role.

## Decision

RBAC per workspace with roles `owner, admin, product, engineer, security, grc, viewer`, evaluated in one authorization module and covered by a permission-matrix test.

## Alternatives considered

- ABAC from day one: flexible, but premature.

## Consequences

- **Positive:** Simple and auditable.
- **Negative:** Fine-grained rules (per product) deferred.
